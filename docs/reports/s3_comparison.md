# 阶段三：受控对照结果

> 日期：2026-11-06。数据：`data/ufw_v1`（Ultra-FineWeb 中英各 1 个分片，训练池约 10 亿 token）。
> 每组 943,718,400 token（900 步 × 1,048,576 token/步），少于一遍训练池，无重复数据。
> 四组数据、顺序、batch、调度（WSD：2% warmup，最后 20% 衰减到 0.1×）完全相同，每组 2 × H100。
> 验证集：中英各 256 个 2048 窗口（来自留出的 2000 篇文档），指标为逐 token 交叉熵（nats）。

## 4. 分析

1. **三值化的真实代价是 0.256 nats（PPL 15.1 → 19.5）。** 这是同数据、同 token、同调度下 B 与最佳 BF16 对照 A2 的差。阶段二里 B 类配置"低于原模型"（3.041 < 3.177）不能解读为三值无损：原模型是发布版（含对话微调），在预训练分布上本身没到最优，A 组只用 BF16 继续训练就降了 0.46。以原模型为基准算出的 recovery（B 为 1.02）因此高估了效果，对外应使用"与 BF16 对照差 0.26"的口径。
2. **收益来自 QAT，而不是多训练（Q6）。** A 组训练 9.4 亿 token 后直接三值化仍为 12.2–12.6，与不训练直接三值化（13.3）几乎相同；BF16 继续训练没有让权重更适合三值化。
3. **差距仍在缩小，未饱和（Q5 的初步证据）。** B − A2 从 151M 时的 0.59 降到稳定段末的 0.37，LR 衰减阶段又降到 0.26。衰减对三值模型的收益（3.130 → 2.970，−0.160）明显大于对 BF16 的收益（2.756 → 2.714，−0.042），说明三值模型在稳定段末仍远未收敛，更长的稳定段很可能继续缩小差距。这支持用更多数据做长训。
4. **以原模型为老师的蒸馏不划算（Q4）。** D 比 B 差 0.022，且吞吐只有 57%。一个可能的原因是：老师（原模型，CE 3.177）在这批数据上比学生最终水平（2.970）还差，KL 项把学生拉向更差的分布。用 A2（CE 2.715）做老师可以检验这一点，见 §5。
5. **QAT 后的主权重只对三值前向有意义。** B/D 按浮点推理 CE 为 9–12，部署和评测都只能用三值模型。这与报告中 BitCPM4 以 fake-quant 形式发布权重的做法一致。
6. **A 组 LR 选择对结论影响很小。** A2 比 A1 好 0.038，远小于 0.256 的三值代价；选更好的 A2 作为对照，结论偏保守。

## 5. 下游评测（`qat/eval_downstream.py`）

设置：MMLU test / CMMLU test / C-Eval val 均 5-shot，取"Answer:"/"答案："后 A–D 四个 token 的 logits 最大者（随机水平 25%）；GSM8K test 8-shot 贪心生成，取 `####` 后或最后一个数字。三值模型先把权重替换为 `codes × scale` 后再以 BF16 推理，与 2-bit 导出后的计算一致。评测数据来自共享盘（LLaMA-Factory 与 OpenCompass 附带的副本），复制在 `eval_data/`。原始输出见 `reports/downstream/*.json`。

| 模型 | 精度 | MMLU | CMMLU | C-Eval | GSM8K |
|---|---|---:|---:|---:|---:|
| 原模型 | BF16 | **50.5** | **66.4** | **68.0** | **30.3** |
| 原模型直接三值化 | 三值 | 24.4 | 25.1 | 24.0 | 0.0 |
| A2：BF16 续训 9.4 亿 token | BF16 | 44.0 | 46.7 | 49.6 | 18.9 |
| B：QAT 9.4 亿 token | 三值 | 23.8 | 25.1 | 23.9 | 1.8 |
| D：B + 原模型蒸馏 | 三值 | 25.5 | 25.3 | 26.6 | 1.3 |

（准确率 %；MC 为样本级准确率。）

分析：

1. **验证 CE 恢复不等于下游恢复。** B 的验证 CE 从 13.33 恢复到 2.97，但三项选择题都停在随机水平，GSM8K 1.8%。生成样例显示 B 能写出通顺、格式正确的解题文本，但推理与知识基本丢失。约 10 亿 token 的 QAT 只恢复了"语言建模"，没有恢复知识与能力。对外不能只报验证 loss。
2. **即使不量化，在纯网页数据上续训也会损失下游能力。** A2 的验证 CE 比原模型好 0.46，但 MMLU −6.5、CMMLU −19.7、C-Eval −18.4、GSM8K −11.4。原模型是经过指令/对齐等后训练的发布版，纯预训练分布续训会冲掉这部分能力。因此三值模型的下游损失，一部分来自数据配比，而非量化本身；后续长训需要混入指令类与数学类数据（§4.2 的计划需要提前执行），并以 A 类对照区分两者。
3. **0.26 nats 的 CE 差距在下游上是"可用"与"不可用"的差别。** A2（CE 2.715）仍保留明显的知识能力，B（CE 2.970）则没有。这与报告中 BitCPM4 用 350B token QAT 的量级一致：本实验只有其约 0.3%。
4. 蒸馏（D）在下游上与 B 同为随机水平，C-Eval 的 26.6 与 B 的差别在噪声范围内（1346 题，标准误约 1.2 个百分点）。

## 6. 结论与后续

- 主线配置定为 **B：渐进切换（前 10%）+ 峰值 LR 3e-3（μP 后隐藏层 7.5e-4）**，不加蒸馏（实验 E 结果出来后再定）。
- 三值代价在 9.4 亿 token 时为 0.256 nats，且仍在下降；但下游能力尚未开始恢复。需要数十 B token 以上的长训测饱和点，且训练数据需加入指令、数学类数据，否则即使 BF16 也会掉下游。
- 实验 E：用 A2 的最终权重做老师，蒸馏权重 0.5 / 0.9（`runs/s3_E_*`，启动脚本 `runs/launch_s3e.sh`），运行中。
